## SDK gateway response bounds

The SDK also treats HTTP response decoding failures as uncertain memory writes, preserving the original request ID. ## Architecture decisions

### Local-first enforcement

The first slice uses SQLite so security rules can be exercised without RPC, wallets with funds, or external APIs. This is a development slice, not proof of decentralized integration. The gateway is split into API, persistence, cryptography, and policy modules so integrations can replace local adapters without moving authorization into the UI or SDK.

### Signed requests

Agents sign a canonical request string containing method, path, body digest, timestamp, and nonce. The gateway checks the recovered address against the registered agent and consumes each nonce. This prevents an agent name in JSON from being accepted as identity.

### Protected actions

The execution endpoint evaluates the live capability and writes an audit decision in the same call. No caller can supply its own authorization decision. A later onchain executor must enforce the same rule at the contract boundary.

### Memory handling

The gateway stores ciphertext with authenticated encryption and records a salted commitment. Updates append versions. Deterministic rules quarantine authorization claims from untrusted sources even if a future classifier recommends accepting them.
