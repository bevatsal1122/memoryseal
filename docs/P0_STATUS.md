# MemorySeal P0 verification status

Status: **in progress**. This is a development prototype; local test success is not a live deployment or security audit. The acceptance target is the complete security workflow in the technical specification, including real ENS, Arkiv and 0G integrations and an enforced action.

## Expanded feature update — 6 November 2026

Organization policies, the local TypeScript SDK, opt-in client-encrypted namespaces, online namespace-key rotation and explicit multi-EVM chain routing are now implemented. Vault lifecycle metadata uses the existing conservative Arkiv outbox mechanism. See [the feature and test guide](TEAM_VAULT_MULTICHAIN.md) and [SDK README](../sdk/typescript/README.md).

The new encrypted mode does not run server-side inference; human release is separate from verified 0G inference. Existing gateway-encrypted records retain their storage mode and offline key-rotation procedure. Additional live chains still require actual deployment configuration/funding. No non-EVM support, cross-chain synchronization, organization multisig custody, or independently attested client-to-provider inference is claimed.

The sections below describe earlier milestones; their references to missing client-held keys, online rotation, TypeScript and multi-chain support are superseded **for the new modes described above**, not retroactive guarantees for legacy data or unconfigured live deployments.

## Website workflow update — 6 November 2026

Implemented the agent console (signed writes, author acknowledgements, reads, local simulations and protected wallet transfers), owner-signed review of low-risk observations, targeted Arkiv publication/reconciliation controls, and matching SDK operations. Schema v9 records exact owner-reviewed commitments; provenance v8 binds signed review evidence. Reviewed memories retain unverified inference and untrusted content labels. Instructions, external content, authorization claims and unsafe ancestry cannot be released through this route.

Validation for this update: Python **246 passed, 6 skipped**; Ruff passed; browser helper/HTTP tests **9 passed**; Arkiv adapter **6 passed**; isolated production build passed with the existing viem/ox bundling warning. The action helper was tested on a real local EVM, including recipient balance changes. UI smoke checks use a simulated wallet/gateway; real MetaMask and live testnet acceptance are still outstanding. Follow [the website test guide](WEBSITE_E2E_TEST.md).

This is a P0 workflow extension, not completion of the full production specification. Client-held keys, online rotation, independent private 0G request binding and P2 integrations remain outstanding. The earlier evidence table below is historical; its references to missing browser controls are superseded by this update, while its live integration limits still apply.

## Specification test coverage

- Authorized writes, unauthorized namespaces, quarantine, namespace filtering, owner-only grants and revoked agents: `tests/test_capabilities.py`, `tests/test_sdk_demo.py`.
- Forged signed memory cannot grant onchain authority; over-limit denial, owner update, allowed retry, stale policy, expiry and revocation: `contracts/test/test_evm.py` and `contracts/test/policy.test.mjs`.
- Unauthorized delegation: the gateway rejects an agent's attempt to grant another agent permission; the local registry scopes an agent's own grant to that agent as owner. Delegation on behalf of another owner is not implemented.
- Memory commitment/encryption and replay resistance: `tests/test_encryption.py`, `tests/test_auth.py`, `tests/test_signatures.py`.
- Concurrent and ambiguous write retries: `tests/test_idempotency.py`; concurrent requests can still duplicate external inference work.
- Inference and provenance checks: `tests/test_inference_flow.py`, `tests/test_zero_g_registry.py`, `tests/test_outbox_worker.py` and adapter tests. These use mocks except where the build record explicitly identifies a public RPC observation.

## Latest local verification

The experimental bridge optionally gates invocation on an operator-supplied strict provider verifier and passes its reported encryption key as a pre-sealing pin. This is still unverified inference: the verifier, baseline, RPC and bridge are trust inputs, and neither the key match nor the bridge receipt proves live execution or actual wire traffic. Local mocked gateway tests cover rejection before bridge invocation and rejection of a response lacking the required receipt. A funded, independently verified end-to-end run remains outstanding.

The latest Python suite passed with 243 passed and 6 skipped after the local policy evaluator changes; Ruff passed. Earlier local EVM, ENS/Arkiv adapter, dashboard Node and standalone Ganache checks also passed. The last dashboard production build passed with a viem dependency bundling warning. Skipped tests and earlier results are not evidence of live integration. See [BUILD_RECORD.md](BUILD_RECORD.md) for the detailed history and verification limits.
